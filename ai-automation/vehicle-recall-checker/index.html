Vehicle Recall Checker

The recall checker was the first trust wedge: VIN input, recall lookup, clear status, and lead capture. It proved the entry behaviour — then opened the path toward broader vehicle trust intelligence.

Role in stack
Entry wedge
First trust action before deeper history products.
Input
VIN
Simple enough for consumer and ops usage.
What we know
Campaign match
Whether a recall exists for the VIN.
What we need
Completion status
Whether the recall was actually repaired.
How it works
Step 1
VIN Input
Consumer or ops submits a 17-character VIN via form, API, or internal workflow.
→
Step 2
Recall API Lookup
VIN is matched against campaign recall databases and OEM reference data.
→
Step 3
Status Classification
Each matched recall is classified as open, completed, or status unknown.
→
Step 4
Action Output
Result returned to user. High-risk cases escalate into trust or inventory review.
Open
An active recall campaign matches this VIN. Completion status is unknown.
Completed
Recall exists and repair has been confirmed by OEM or dealer.
Status Unknown
Insufficient data to confirm or deny recall repair completion.

MVP logic

  • Accept VIN from a public or internal workflow.
  • Check recall campaign data and supporting VIN-match logic.
  • Return open, completed, or status unknown.
  • Escalate uncertain or risky cases into trust or inventory review.

Why this mattered commercially

Recall intelligence improved trust and compliance immediately, but it also revealed a deeper opportunity: if a user is already checking a VIN for trust, Cars24 can answer bigger questions around service history, odometer consistency, and broader vehicle risk.
