The manual starting point

Manual listing QC was slow, repetitive, and hard to scale.

During dealer onboarding, each vehicle needed to be checked across DMS data, Glass's data, and custom quality rules. That meant people spent time comparing sources, spotting missing values, resolving conflicts, and deciding if a listing was safe to publish.

Manual man-hours
~80 hrs

2 interns × 5 days to review 400 cars

Automated
~20 min

for 2,012 cars — a 240× reduction in effort

Before

Spreadsheet-heavy review

  • Vehicle-by-vehicle checking across multiple data sources
  • Repeated validation of missing and conflicting values
  • Manual mismatch resolution and publish-readiness judgment
  • Long turnaround times with limited leverage
  • Weak run-over-run memory and visibility
What needed to change

QC had to become a system

  • Compare sources consistently at field level
  • Score every car the same way every run
  • Isolate exceptions instead of reviewing everything
  • Persist state so new, changed, and delisted VINs are visible
  • Give ops a live dashboard instead of a one-off output
Why this matters now

At 5,000 vehicles, manual QC becomes an operational bottleneck.

This is not a nice-to-have. If inventory scales without a QC system behind it, onboarding slows down, manual effort grows linearly, and decision quality becomes harder to keep consistent.

What was built

A smart QC analyst, turned into a repeatable system.

The engine reads multiple data sources, VIN-matches records, resolves low-risk conflicts, scores each vehicle, flags exceptions, persists run history, and publishes live operational outputs.

Module 01

Config

Rules, scoring, thresholds, normalization, routing, and AI trigger behavior live in one place.

Module 02

Reader

Pulls DMS and Glass's source data, normalizes it, and aligns records for comparison.

Module 03

QC Engine

Runs deterministic checks, conflict handling, scoring, and publish-readiness classification.

Module 04

AI Layer

Assistive where configured, but not required for the core workflow to keep running.

Module 05

DB5 State Store

Tracks run-over-run state, changes, status transitions, and VIN lifecycle history.

Module 06

Outputs

Writes JSON outputs, a live Google Sheets dashboard, and DMS push-ready decisions.

Technical view

Config drives the checks, the reader aligns DMS and Glass's data, the QC engine resolves and scores vehicles, DB5 stores run history, and outputs feed Google Sheets plus DMS-ready decisions.

How it works

Two source feeds in. Decision-ready outputs out.

The workflow is designed to stay easy to explain: read inputs, run deterministic QC, compare against persistent memory, use AI only where configured, then update operational outputs that support consistency, trust, and faster readiness.

Inputs

DMS and Glass's data arrive as the two source feeds for matching and QC.

Decision engine

The QC engine creates the current run, then compares it with DB5 to classify what changed.

AI assist

Weave only steps in where configured. The core rules path still works without it.

Outputs

The result is an updated dashboard, a DMS push stub, and a complete change log.

AI-assisted, not AI-dependent

The deterministic QC path is the backbone. AI sits beside it as an assistive layer where configured, which means the system still remains stable even if AI endpoints are unavailable.

Technical view

The core loop is match, resolve, normalise, validate, score, diff against DB5, and then write outputs. AI is optional routing, not a required dependency.

Where AI fits

AI-assisted, not AI-dependent.

What AI does here

  • Adds an assistive layer where configured in the workflow
  • Helps the system scale smarter on selected decision paths
  • Works alongside rules, scoring, and persistent state
  • Can run with concurrency when endpoints are available

What AI does not do here

  • It does not replace deterministic QC rules
  • It does not make the workflow unstable if turned off
  • It does not eliminate manual review for exception cases
  • It is not the sole reason the productivity gain exists
Core message

We are not using AI for the sake of AI. We are using automation intelligently to remove repetitive work, improve consistency, and help the team scale.
